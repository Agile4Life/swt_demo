# Coach Health Metrics — existing API amendment

GET /api/v1/members/{memberId}/health-metrics and GET /api/v1/health/metrics/my retain their DTO. POST /api/v1/members/{memberId}/health-metrics and POST /api/v1/health/metrics append records. POST allows assigned COACH, CENTER_MANAGER, or RECEPTIONIST with an open GRANTED check-in recorded by that receptionist today in Asia/Ho_Chi_Minh. Staff can only append; PUT/DELETE/history GET remain forbidden to Receptionist. MEMBER cannot write. The check-in row is locked and revalidated before the measurement insert. Member must be active and not deleted. CurrentCoachMembers is checked independently by the service and fails closed if unavailable; historical assignment alone does not grant access.

Values: positive decimal >=0.01 with at most two decimal places and entity-compatible precision. weight/muscle_mass use kg; height/waist cm; body_fat % and <=100; bmi unit null/empty. No BMI calculation. Invalid measurement: HTTP400 INVALID_HEALTH_MEASUREMENT. Missing assignment: HTTP403 COACH_MEMBER_NOT_ASSIGNED. Audit recordedBy comes from JWT; recordedAt is server receipt time in Asia/Ho_Chi_Minh. Client timestamps are not accepted as measurement dates. No schema change or backfill. Runtime DB/E2E not verified. Receptionist scope is the leader-approved intake policy: same actor, same center-day, still open; a payment or member search alone is not sufficient. No new role-permission key exists for health writes in current seed.

Updating a measurement to BMI accepts null unit and clears any previous kg/cm unit; explicit incompatible units remain rejected.
